# 工具输出压缩 Token 实验

日期：2026-09-26

## 结论

在 6 类固定工具输出样本上，`shrink_output()` 将输入文本的估算 token 从 **4,198** 降到 **890**，减少 **78.80%**；被规则识别的重要错误/警告行保留率为 **100%（5/5）**。git 状态样本没有重复到触发收益，因此保持原样。

| 样本 | 原始估算 token | 压缩后 | 减少 | 重要行保留 |
| --- | ---: | ---: | ---: | ---: |
| pytest | 759 | 73 | 90.38% | 1/1 |
| build | 190 | 34 | 82.11% | 1/1 |
| logs | 1,312 | 39 | 97.03% | 2/2 |
| git | 323 | 323 | 0.00% | 1/1 |
| json | 1,198 | 322 | 73.12% | - |
| mixed | 416 | 99 | 76.20% | 2/2 |
| **合计** | **4,198** | **890** | **78.80%** | **5/5** |

## 如何复现

在仓库根目录执行：

```bash
python3 benchmarks/benchmark_output_compaction.py
```

原始结果保存在 [`results/2026-09-26-output-compaction.json`](results/2026-09-26-output-compaction.json)。

## 解释与边界

- 这是压缩机制实验，不是真实模型 A/B，也没有调用 provider。
- token 数由 `estimate_request_tokens()` 的 tokenizer-free 估算得到，不等于 OpenAI、Codex 或其他 provider 的实际计费 token。
- 因此 78.80% 只能说明这些固定样本送入模型前的文本体积下降，不能直接承诺同等比例的账单节省。
- 没有模型质量对照，不能据此声称回答质量不变。
- 压缩器是确定性的抽取式压缩：去 ANSI、合并连续重复行，并保留头部、重要错误/警告行和尾部；不是语义摘要。
- 生产使用时可通过 `--shrink-archive-dir` 归档原始输出，以便审计或恢复。
